## 2. Principal Architect & Staff Cybersecurity Audit Matrix

Below is the strict, no-flattery code and security audit matrix across Clean Architecture boundaries, OWASP ASVS L2 controls, and UX compliance:

| ID | Severity | File / Location | Flaw Explanation | Exact Code Fix |
|---|---|---|---|---|
| **AUD-P3-01** | **Critical** | `backend/src/ShopVerse.Infrastructure/Identity/TotpService.cs` (L37–65) & `ShopVerse.Domain/Identity/User.cs` (L31–44) | **RFC 6238 §5.2 TOTP Replay Vulnerability**: `VerifyTotpCode` checks if the 6-digit code matches `currentCounter + offset` (`-1, 0, +1`), but does not track the last accepted time-step counter on the `User` aggregate. An attacker who intercepts a valid 6-digit TOTP code can replay it multiple times within the 90-second window. | Add `public long? LastUsedTotpTimeStep { get; private set; }` to `User` (and EF Core config/migration). Update `ITotpService.VerifyTotpCode` to `bool TryVerifyTotpCode(string base32Secret, string code, DateTimeOffset timestamp, long? lastUsedTimeStep, out long matchedTimeStep, int windowSteps = 1)` which rejects any step $\le \text{lastUsedTimeStep}$, and call `user.RecordTotpTimeStepUsed(matchedStep, now)` upon verification. |
| **AUD-P3-02** | **High** | `backend/src/ShopVerse.Infrastructure/Identity/IdentityService.cs` (L288–326) | **Unvalidated Google OIDC Token Acceptance**: `GoogleLogin` accepts any arbitrary string $\ge 10$ characters and hashes it to synthesize a `google-sub-*` ID, trusting client-supplied `ExpectedEmail` and `FullName`. In a real/test OIDC flow, a malformed token or expired token (`exp < now`) or wrong issuer/audience must be rejected. | Add structured Google OIDC JWT validation in `IdentityService.GoogleLogin`: if the token is a 3-part JWT (`header.payload.signature`), decode and validate `iss` (`https://accounts.google.com` or `accounts.google.com`), `exp > utcNow`, `email_verified == true`, `sub`, and `email` from the signed payload claims (never trusting raw unverified body overrides when JWT claims exist), while still supporting deterministic signed test tokens. |
| **AUD-P3-03** | **High** | `backend/src/ShopVerse.Api/Controllers/AuthAndIdentityControllers.cs` (L12–23, L245–254, L332–339) | **Clean Architecture Boundary Violation (DIP)**: Controllers in `ShopVerse.Api` directly reference `using ShopVerse.Infrastructure.Identity;` and inject concrete class `IdentityService` instead of programming against an Application-layer interface `IIdentityService` in `ShopVerse.Application.Identity` (`docs/ARCHITECTURE.md` §2). | Define `public interface IIdentityService` in `ShopVerse.Application/Identity/IdentityContracts.cs`, implement `IIdentityService` on `IdentityService`, register `builder.Services.AddSingleton<IIdentityService, IdentityService>()` in `Program.cs`, and remove `using ShopVerse.Infrastructure.Identity;` from `AuthAndIdentityControllers.cs`. |
| **AUD-P3-04** | **High** | `backend/src/ShopVerse.Api/Program.cs` (L174–188) & `AuthAndIdentityControllers.cs` | **Missing Strict Auth Endpoint Rate Limiting**: `01_PROJECT_BRIEF.md` §11.1 & `API_CONTRACT.md` §2.1 mandate `5 req/min per IP` on login/OTP/register/password-reset endpoints to block credential stuffing and SMS pumping, but `Program.cs` only configures a 100 req/min global limiter. | Register named rate limiter policy `"AuthStrictPolicy"` (FixedWindow, `PermitLimit = 5`, `Window = 1 min`, `QueueLimit = 0` per IP) in `Program.cs` and decorate `Register`, `Login`, `VerifyOtp`, `SendOtp`, `ForgotPassword`, and `ResetPassword` with `[EnableRateLimiting("AuthStrictPolicy")]`. |
| **AUD-P3-05** | **High** | `backend/src/ShopVerse.Api/Controllers/AuthAndIdentityControllers.cs` (L119–139) & `IdentityService.cs` (L543–565) | **Broken Single-Session Logout & Expired-JWT Logout**: 1) Calling `POST /api/v1/auth/logout` with an expired Access JWT does not revoke the `refresh_token` in the DB because `_currentUser.UserId` is null. 2) When `_currentUser.UserId` is present, `RevokeSessions(userId, new(RevokeAll: false))` with `SessionId: null` iterates over **all** non-revoked tokens of the user and revokes every device session instead of only the current cookie's token family. 3) Missing `RevokeAllExceptCurrent` filter. | Add `RevokeRefreshTokenByCookie(string? rawRefreshToken, string? clientIp)` to `IIdentityService` so `Logout()` always revokes the exact token family matching the `refresh_token` cookie even if the 15m Access JWT has expired. ## 3. Remediation & Verification Execution Plan (Upon Approval)

### Step 1: Backend Domain, Application & Infrastructure Hardening (`backend/src/`)
1. **`ShopVerse.Domain/Identity/User.cs` & `OtpCode.cs`**:
   - Add `LastUsedTotpTimeStep` (`long?`) and `RecordTotpTimeStepUsed(long timeStep, DateTime utcNow)` to `User.cs` to prevent RFC 6238 TOTP replay attacks.
   - Align `OtpCode.MaxVerificationAttempts = 3` with `DATA_MODEL.md` §2.1.
2. **`ShopVerse.Application/Identity/IdentityContracts.cs`**:
   - Extract complete `IIdentityService` interface into `ShopVerse.Application.Identity`.
   - Update `ITotpService` with `TryVerifyTotpCode(..., long? lastUsedTimeStep, out long matchedTimeStep, int windowSteps = 1)`.
   - Add `SendOtpRequestDto`, `SendOtpResponseDto`, and `RevokeAllExceptCurrent` on `RevokeSessionsRequestDto`.
3. **`ShopVerse.Infrastructure/Identity/TotpService.cs` & `IdentityService.cs`**:
   - Implement RFC 6238 replay protection in `TotpService` and `IdentityService`.
   - Implement structured OIDC JWT payload claim validation (`iss`, `aud`, `exp`, `email_verified`, `sub`) in `GoogleLogin`.
   - Implement `SendOtpAsync`, `RevokeRefreshTokenByCookie`, `RevokeAllExceptCurrent`, and strict 3-level Bangladesh `Division -> District -> Upazila` parent-child validation.
   - Update `ShopVerseDbContext.cs` and `202610290001_Phase3IdentityAndAccess.cs` with `last_used_totp_time_step`.
4. **`ShopVerse.Api/Controllers/AuthAndIdentityControllers.cs` & `Program.cs`**:
   - Inject `IIdentityService` (removing Infrastructure namespace coupling from API controllers).
   - Register and apply `"AuthStrictPolicy"` rate limiter (`5 req/min per IP`).
   - Add `POST /api/v1/auth/otp/send` and `PUT /api/v1/sellers/{sellerId:guid}/resources` (for cross-seller write isolation testing).

### Step 2: Frontend Storefront, Console & Interactive Workbench Remediation (`frontend/` & `/src/`)
1. **`frontend/apps/web/src/components/auth/AuthModal.tsx` & `frontend/apps/console/src/app/login/page.tsx`**:
   - Replace internal phase/debug header tags with clean, domain-authentic MECHWARE industrial copy in both English and Bangla.
2. **`frontend/apps/web/src/app/[locale]/account/addresses/page.tsx`**:
   - Implement complete Address Book CRUD (saved address cards with Default Shipping / Default Billing indicators, Add / Edit form with cascading Bangladesh Division → District → Upazila selector, Delete button, and GDPR export/anonymize actions) using strict semantic design tokens (`0` raw hex/palette violations).
3. **`/src/components/Phase3IdentityWorkbench.tsx` & `/src/App.tsx`**:
   - Add full Light & Dark mode support (`theme` prop) with WCAG AA contrast in both themes.
   - Add interactive Address Book CRUD & TOTP Replay Guard demonstration alongside the Token Family & Seller Isolation simulators.

### Step 3: Automated Unit, Integration & UI Tests + 16-Viewport Visual QA Matrix + GitHub Sync
1. **Expand Backend & Frontend Test Suites**:
   - Add unit & integration tests in `IdentityPhase3UnitTests.cs`, `AuthAndRbacIntegrationTests.cs`, and `frontend/packages/ui/tests/components.test.mjs` covering:
     - TOTP replay rejection within the same 30s time-step window.
     - OIDC expired/invalid issuer token rejection.
     - 3-level Bangladesh Division → District → Upazila mismatch rejection.
     - Single-family logout revocation via `refresh_token` cookie & `RevokeAllExceptCurrent`.
     - Cross-seller `PUT` modification rejection (`403 Forbidden`).
2. **Capture Visual QA Screenshots**:
   - Render and capture screenshots of the live app across `360px`, `768px`, `1280px`, and `1920px` in **Light Mode** and **Dark Mode**, and in **English (`EN`)** and **Bangla (`BN`)**.
3. **Run All Verification Scripts & Push to GitHub**:
   - Run `node frontend/packages/config/lint-tokens.mjs`, `node frontend/packages/ui/scripts/verify-contrast.mjs`, `node --test frontend/packages/ui/tests/components.test.mjs`, and `compile_applet`.
   - Sync all changes to `/tmp/mechware-fresh`, commit, and push to `origin/main` on GitHub, then present the final **Before/After Evidence Table**.
