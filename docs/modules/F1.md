## HANDOFF (F1.1 -> console fulfilment F1.3, web tracking)
- **Endpoints** (all `orders.fulfil` = Support + Admin; Finance, Moderator, Seller, Buyer 403; anonymous 401; no step-up): `POST /api/v1/admin/orders/{orderId}/processing` (Confirmed → Processing), `.../packed` (Processing → Packed), `.../ship` (Packed → Shipped), `.../delivered` (Shipped or OutForDelivery → Delivered). Body `{rowVersion}`; ship adds `courierName`, `trackingNumber`, `trackingUrl?`. Answer 200 `{data:{id, orderNumber, status, rowVersion, shipments:[{id, courierName, trackingNumber, trackingUrl, shippedAtUtc, deliveredAtUtc, createdBy}]}}`: keep the new `rowVersion` for the next button.
- **Errors:** missing `rowVersion` 400; stale `rowVersion` 409 `ORDER_CHANGED` (reload); wrong status 409 `ORDER_INVALID_TRANSITION` (e.g. ship of a cancelled order); field errors 400 with `courierName` / `trackingNumber` / `trackingUrl`; unknown order 404. Checked in this order: auth, fields (ship), rowVersion present, order exists, rowVersion current, status.
- **Field rules (domain + DB CHECKs):** courier name plain text (`PlainText.Clean`, white space collapsed), 2-80; tracking number 1-60 ASCII letters, digits, dashes (trimmed, case kept); tracking link optional: absolute https, default port, no user name, max 500, host exactly one of `Shipment.TrackingUrlHosts` (steadfast.com.bd, pathao.com, redx.com.bd, paperfly.com.bd, ecourier.com.bd) or a subdomain of one. Why an allow-list: the link is shown to buyers on our own pages, so a free URL lets a careless or stolen staff account plant a phishing link; empty is always fine (the number alone is enough).
- **Staff detail** `GET /api/v1/admin/orders/{id}` now has `rowVersion` (send it to the moves) and `shipments` (same shape as above). The order's `events` show each move with the staff id; the ship event's reason is "Shipped with {courier}, tracking {number}".
- **Buyer** `GET /api/v1/orders/{id}` and `by-number/{n}` now have `shipments: [{courierName, trackingNumber, trackingUrl, shippedAtUtc, deliveredAtUtc}]` (oldest first, empty before shipping). Never the shipment id or the staff id (whitelist test). Show the link only when present, `rel="noopener noreferrer"`.
- **Payment rule:** the existing state machine decides. Only `Order.Confirm` reaches Confirmed (captured gateway payment or accepted credit terms) and Processing needs Confirmed, so an unpaid order can never be shipped or delivered. There is no COD path in code yet; see owner decision 2.
- **Concurrency:** each move is one transaction that locks only the `orders` row `FOR NO KEY UPDATE` (no payment, company or promotion touched, so no cycle with the global order payments → orders → companies → promotions). Parallel cancel + ship: one 200, the other 409 (`ORDER_NOT_CANCELLABLE` or `ORDER_CHANGED`), never 500 (4 rounds tested).
- **Audit + outbox:** audit actions `order.processing_started`, `order.packed`, `order.shipped` (with courier, number, link), `order.delivered` (entity `orders`); outbox events `OrderProcessingStartedEvent`, `OrderPackedEvent`, `OrderShippedEvent` (courier, number, link), `OrderDeliveredEvent`. No publisher sends mail for them yet (the notification publishers ignore unknown events): a mail unit (F3) adds the "shipped" mail.
- **Deadlines:** unchanged rule, now tested: shipped counts as handed over (`OrderDeadlineService.HandoverOpen` = Confirmed, Processing, Packed), delivered closes the delivery deadline; the overdue list and `?overdue=` of the staff list stop flagging them.
- **Schema:** table `shipments` (id, order_id FK restrict, courier_name, tracking_number, tracking_url, shipped_at, delivered_at, created_by FK users, created_at, updated_at), CHECKs `ck_shipments_courier_name`, `ck_shipments_tracking_number`, `ck_shipments_tracking_url`, `ck_shipments_delivered_after_shipped`, unique `ux_shipments_order` (one shipment per order; F1.4 replaces this index, the API already returns a list). Migration proven Up/Down/Up on a scratch DB; not applied to `mechware` (run `Mechware.Worker migrate`).
- **Mutants killed (each alone):** state machine allows Cancelled → Shipped; rowVersion compare removed; `RequirePermission` dropped from ship; tracking number not validated; Shipped added to `HandoverOpen`.
- **Owner decisions (open, defaults applied):** (1) who may fulfil: Support + Admin (new `orders.fulfil`), not Finance, no authenticator code; (2) COD: none in code; when COD comes (E3.5/E5) decide whether a COD order is Confirmed at placement and whether Delivered must record the cash collected; (3) new lifecycle edge Shipped → Delivered (manual, no "out for delivery" step), OutForDelivery stays for courier scans; (4) the tracking-link host list (above) and whether other couriers (Sundarban, SA Paribahan, Karatoa) are added; (5) whether a credit order of a company on overdue hold may still be shipped (today: yes, the hold only blocks new orders); (6) no undo: a wrong move (e.g. shipped by mistake) has no correction endpoint yet; (7) delivered by staff without proof of delivery (photo/signature) is accepted.
- **Not in F1.1:** console buttons (F1.3), web tracking display (a web unit; the field is there), mails (F3), courier API/webhook (F1.2), partial shipments (F1.4), DeliveryFailed/returns (F2).
