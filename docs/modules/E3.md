## HANDOFF (E3.1 + E3.2)
**E3.1** `frontend/packages/api-client/src/cart.ts` (`createCartApi(client)`: `get`, `addItem`, `setItem` (0 removes), `removeItem`, `clear`; each returns the unwrapped `CartView`) and `cart-model.ts` (types `CartView/CartLine/CartNotice`, `cartNoticeMessageKey`, `noticeMessage`, `canProceedToCheckout`, `groupNotices`, `lineTotalIsConsistent/subtotalIsConsistent`, `clampCartQuantity/stepCartQuantity/minCartQuantity` (UI hints only), `classifyCartError` (network/5xx/CART_UNAVAILABLE -> `unavailable`, never "empty"), `shouldRefetchAfter`). Response types are hand-written because `schema.d.ts` has no response bodies for the cart routes. Credentials: the shared `MechWareApiClient` already sends `credentials: 'include'` and the Bearer token when one is in memory, so no client change was needed; the API CORS allows only `localhost:3000/3001` (+ prod hosts) with credentials. Tests `frontend/packages/api-client/tests/cart-model.test.ts` (7).
**E3.2** `/cart` (`apps/web/src/app/[locale]/cart/page.tsx`): server shell (h1, `robots: noindex,nofollow`, no JSON-LD) + client island `components/cart/CartPageView.tsx`, which waits for the auth session check (`useAuth().status !== 'loading'`) and then `GET /cart` in the browser (guest cookie is HttpOnly on the API origin, so only the browser can send it). Shows only server values; per-line notices (all 8 kinds, plain text EN/BN, `Cart` messages), orphan notices (cartFull) above the list, summary with subtotal, checkout link to `/checkout` (disabled span + reason when a line has outOfStock/unavailable), empty state -> `/search`, skeleton `CartSkeleton.tsx`, error block with retry (never an empty cart on failure; a failed change keeps the shown cart and adds an alert). Controls lock while any request is in flight; qty edits debounced 600 ms and serialised in a queue; 409 (`CART_BUSY/CHANGED/INSUFFICIENT_STOCK/CART_FULL`) and 404 trigger an automatic refetch. Header: `components/layout/HeaderCart.tsx` (fixed-size link, badge = number of different lines, fetched at idle after the session check, updated by the `mw:cart-changed` event in `lib/cart-events.ts`). PDP: `ProductView.tsx` got an "Add to cart" button (variant id + clamped quantity only; cart code is a dynamic import on first click; success text + "View cart" link, error text). "Add to quote" stays disabled.
**Gaps / follow-ups:** `cartMerged` notices from login/refresh are not shown (the web client's `restoreSession()` drops the envelope; the cart page shows the post-merge notices from `GET /cart` instead). No "clear cart" button yet (`api.clear` exists). Line titles are plain text (the cart view has no product slug, so no link to the PDP: backend could add `slug` to `CartLine`). Cart prices are tax-inclusive display prices (company prices later). `/checkout` page does not exist yet (middleware sends signed-out users to login). The guest-cart limit (20 new carts per IP per hour) is hit when the E2E is re-run many times on one API process; restart the API between full runs.
