**Behaviour.** Flow state lives in the URL (`step`, `a` address, `c` company, `s` site, `cc` cost centre, `po`, `k` Idempotency-Key), no storage, so a refresh keeps the step and the key. The cart is the server's (read on every load); empty goes to `/cart`; a line with a blocking notice keeps the buyer on step 1. Step 1: personal (saved addresses + "add address" form, Division -> District -> Upazila from `GET /locations/bd`, BD mobile checked like the server) or company (only active companies where the user holds the Buyer role: site list with default preselected, cost centre select when the member may list them, PO number validated 1-40 chars `A-Za-z0-9 -_.#/`). Step 2: `POST /orders/shipping-quote`, per-seller shipping only when more than one seller, free-shipping note, the 422 codes in plain text with SKUs; Place order is disabled until the quote is OK. Place: re-reads the cart first and stops if price/qty/etag changed (nobody pays a price they did not see); one key per attempt, kept for 5xx/network/busy/429 (a retry replays, never a second order), new after any definitive refusal or when the request changed; double click = one POST; 409 stock/unavailable refresh the cart; 401 goes to login with `returnTo`. Success: best-effort `DELETE /cart` (the API does not clear it on placement) then `/checkout/confirmation?order=<number>&id=<orderId>`; the placeholder reads `GET /orders/{id}` for the status and shows "sent for approval" for `pending_approval`.
