## HANDOFF (G5.5 -> console order list/detail, backend built, NOT committed)
- **Built (backend only, no migration):** `GET /api/v1/admin/orders` and `GET /api/v1/admin/orders/{id}`, both `orders.view_all` (Support, Finance, Admin; anonymous 401, others 403), both `Cache-Control: private, no-store`, each read in one REPEATABLE READ snapshot. Files: `Application/Orders/StaffOrderContracts.cs`, `Infrastructure/Orders/StaffOrderReadService.cs`, `AdminOrdersController`, DI line, test `IntegrationTests/Orders/StaffOrderReadEndpointsTests.cs` (9 tests, own host). Not named "G5.5" in the card's own list (that is users and roles); this unit is G5.5b.
- **List:** `?status=` (wire name, e.g. `pending_payment`, `confirmed`) `&companyId=` `&orderNumber=` (prefix, case-insensitive) `&from=&to=` (Dhaka dates `yyyy-MM-dd`, both inclusive; from after to is 400) `&paymentState=` (`none`, `on_credit`, `pending`, `captured`, `failed`, `needs_refund`, `refunded`) `&overdue=` (true = past a legal deadline now, false = not) `&page=&pageSize=` (max 50, newest first). Any bad filter is 400 with the usual error body. Answer `{data:{items,page,pageSize,totalCount}}`, item = `{id, orderNumber, status, companyId, companyName, grandTotalMinor, paymentState, placedAtUtc, legalDeliveryDeadlineUtc, courierHandoverDeadlineUtc, deliveryOverdue, handoverOverdue, source:"cart"|"quote", quoteNumber}`. No buyer name, phone or address.
- **Detail:** `{data:{id, orderNumber, status, currency, taxMode, placedAtUtc, confirmedAtUtc, paymentDueAtUtc, legalDeliveryDeadlineUtc, courierHandoverDeadlineUtc, deadlineSameCity, purchaseOrderNumber, subtotalMinor, discountMinor, taxMinor, shippingMinor, grandTotalMinor, source, quote:{quoteId,number,versionId}|null, companyId, companyName, buyer:{userId,name,phone}, shipTo:{recipientName,line1,line2,upazila,district,division,postalCode,phone,siteName}|null, paymentState, paysOnCredit, credit:{status,dueOn,chargedMinor,outstandingMinor}|null, subOrders:[{id,subOrderNumber,sellerId,storeName,status,shippingMinor,totalMinor,lines:[{variantId,sku,title,quantity,unitPriceMinor,vatRate,grossMinor,discountMinor,netMinor,taxMinor,totalMinor,priceSnapshot:{source,basis,priceListId,priceListVersion,contractRef,publicUnitPriceMinor,quoteLineId}}]}], events:[{sequence,fromStatus,toStatus,actorId,reason,atUtc}], payments:[{id,method,status,amountMinor,currency,createdAtUtc,capturedAtUtc,refunds:[{id,amountMinor,status,reason,requestedBy,decidedBy,decidedAtUtc,createdAtUtc}]}]}}`. Unknown id 404. Money is minor units (poisha). Status and payment/refund states are snake_case wire names. Refund `status`: `requested`, `processing`, `completed`, `rejected`, `failed`.
- **Never sent (field whitelist test):** provider reference, payment note, provider refund reference, webhook events, cost/margin/commission, any card data. Buyer name/phone and the delivery address are personal data: shown only on the detail (the route needs `orders.view_all`); the service never logs them. Event actors are ids only (no staff email).
- **Interpretations:** (1) `paymentState` is the money-bearing payment (captured, refunded, needs_refund) else the latest attempt, same rule as the buyer's order; no payment is `on_credit` when the order pays on credit, else `none`. (2) `orderNumber` is a prefix filter (letters, digits, dash, max 40). (3) `companyName` is the company's legal name. (4) `credit` exists only for a charged credit order; `status` open/partially_paid/paid/overdue/cancelled as the buyer sees it, `dueOn` a Dhaka date. (5) `overdue` uses the same deadline rules as `GET admin/orders/overdue`.
- **Indexes:** no migration. On 60,000 scratch orders (throwaway probe, deleted) the unfiltered newest-first page took 18 ms (seq scan + top-N sort), status filter 9 ms via `ix_orders_status`, date range 16 ms, number prefix 7 ms. Revisit with an index on `placed_at` (and `company_id`) when orders pass about 500,000.
- **Tests:** permission matrix, each filter, Dhaka midnight edges (17:59:59Z vs 18:00:00Z), paging and the 50 limit, 13 bad filters, whitelist of JSON names, no-store, cart order detail (lines, events, payments, refund, no secrets), quote order on credit (quote link, price source `quote`, credit open). Mutant: removing `RequirePermission` from the detail route is killed by the permission matrix test.
