## HANDOFF (E8.1)
**Moved (backend only, no endpoints, no tariff data anywhere):** `backend/src/Mechware.Domain/Shipping/` (`ShippingRateCard`, `ShippingZone`, `ShippingCalculator`), `backend/src/Mechware.Application/Shipping/IShippingRateProvider.cs`, `backend/src/Mechware.Infrastructure/Shipping/ShippingRateProvider.cs` (AsNoTracking, split query, active zones only), `backend/src/Mechware.Infrastructure/Persistence/Configurations/ShippingConfigurations.cs`, migration `AddShippingZones` (tables `shipping_zones`, `shipping_zone_districts`, `shipping_rate_bands`; empty). Tests: `~Mechware.UnitTests.Shipping` and `~Mechware.IntegrationTests.Shipping`.

**Model.** Zone = code, EN/BN name, active flag, a set of **district** ids (`bd_locations` rows with level `district`; FK, restrict) and one rate card. Rate card = weight bands `(maxGrams, feeMinor)` + optional free-shipping threshold (subtotal >= X) + optional heavy-unit grams + optional oversize side mm + fee cap. A district can be in only one zone: the primary key of `shipping_zone_districts` is `district_id` (DB refuses), the domain refuses a duplicate in one zone, the calculator refuses a district found in two zones passed to it. The existing `BdLocation.ShippingZone` text column (`inside_dhaka` ...) is NOT used by this model; E8.4 may drop or ignore it.
**Calculator** `ShippingCalculator.Calculate(zones, districtId, lines, orderSubtotalMinor)` returns `Priced(ZoneId, PerSeller[], TotalMinor, FreeShippingApplied)`, `QuoteOnly(Reasons[])` or `NoZone`; throws `ValidationException` for no weight (`NO_WEIGHT`), quantity <= 0, empty order, negative subtotal.
- Units: weight whole grams (`ShippingLine.GramsFromKg` = ceiling of `ProductVariant.WeightKg * 1000`), sides whole mm (`MmFromCm` = ceiling of cm * 10; sides live on `Product`, not the variant). Money poisha, no floats.
- One parcel group per seller: seller weight = sum(qty * unit grams); fee = first band with `weight <= maxGrams` (exactly maxKg stays, +1 g moves up). Heavier than the last band = `QuoteOnly` (`ABOVE_LAST_BAND`), never a guessed fee.
- Free shipping: order subtotal >= threshold makes every seller fee 0 (priced, `FreeShippingApplied`). Quote-only wins over free.
- Quote-only rules: any single unit > `HeavyUnitGrams` (`HEAVY_ITEM`), any side > `OversizeDimensionMm` (`OVERSIZE_ITEM`; unknown sides are not oversize), or above last band. Reasons carry variant/seller ids. The brief has no product-level heavy flag, so this is a configurable rule, as asked.
- Total = exact sum of per-seller fees (computed once); fee <= cap; band fees must be non-decreasing and <= cap (card validation), so heavier is never cheaper.
- `QuoteOnly` is the whole order, not per seller (one decision for staff).

## HANDOFF (E8.2)
**Moved (backend only):** seam `backend/src/Mechware.Application/Shipping/IOrderShippingQuoter.cs` (codes `SHIPPING_NOT_AVAILABLE`, `SHIPPING_QUOTE_ONLY`, `VARIANT_WEIGHT_MISSING`), implementation + `ShippingOptions` in `backend/src/Mechware.Infrastructure/Shipping/OrderShippingQuoter.cs`, pricing step in `backend/src/Mechware.Infrastructure/Orders/OrderService.cs` (`PriceAsync`, `DistrictIdAsync`, `QuoteShippingAsync`), new 422 exception `backend/src/Mechware.Domain/Common/Exceptions/UnprocessableException.cs` (mapped in `GlobalExceptionHandlingMiddleware`), PO number on `Order` (`NormalisePurchaseOrderNumber`), migration `AddOrderPurchaseOrderNumber` (`orders.purchase_order_number varchar(40)` + `ix_orders_company_po`), endpoint `POST /api/v1/orders/shipping-quote`. Tests: `~Mechware.UnitTests.Shipping`, `~Mechware.IntegrationTests.Orders` (`OrderShippingTests`, `OrderShippingWithoutZonesTests`, `OrderShippingStartupTests`, `OrderShippingApiTests`).

**How shipping is priced now.** `PriceAsync` loads the variants (weight from `ProductVariant.WeightKg`, sides from `Product`), applies promotions, prices the goods once with zero shipping to get the **free-shipping basis** = the sum of the line totals (after discounts, VAT included, shipping excluded; the same number in VAT-inclusive and VAT-exclusive orders, what the buyer sees), asks the quoter, then prices again with each seller's fee in `SellerTerms`. `OrderPricing` adds each fee once to its sub-order total; grand total = sum of sub-order totals. The client sends no money and nothing it sends is read (tamper test over HTTP).
- **Destination:** addresses and company sites keep the district as text (EN or BN name, checked against the location list when saved). `DistrictIdAsync` looks it up in `bd_locations` (level `district`; by name, then by division if two share a name). No match or ambiguous: null, which shipping refuses. The id is also written into the order's ship-to snapshot as `districtId` (E8.3 needs it for "same city"). No address migration was needed.
- **Refusals (HTTP 422, nothing reserved, no order):** no zone serves the district or district unknown: `SHIPPING_NOT_AVAILABLE`. Heavy, oversize or above the last band: `SHIPPING_QUOTE_ONLY` with `details[] = {field: reason code, message: SKU}` (buyer must use RFQ, D4). Variant weight <= 0: `VARIANT_WEIGHT_MISSING` naming the SKUs (checked before the calculator, never a 500, never free).
- **No zones yet (decision):** `Shipping:AllowFreeWhenNoZones`. Unset = on in Development/Testing, off elsewhere. On = shipping 0 **only while no active zone exists at all**; once one zone exists every destination is priced or refused. Outside Development/Testing the API refuses to start with it on (production fails closed). The Worker never places orders and gets the default (off).
- **VAT on shipping: NOT decided.** The fee stays a final amount with no VAT split (unchanged `OrderPricing` treatment; `TODO(E8, owner + tax adviser)` in `PriceAsync`). If shipping must carry VAT, it belongs in `OrderPricing` (one place), not in the quoter.
- **Preview:** `IOrderService.QuoteShippingAsync` / `POST /api/v1/orders/shipping-quote` (auth like placement; body = lines, shippingAddressId, companyId, couponCodes, shipToSiteId) returns `{perSeller:[{sellerId, shippingMinor}], totalMinor, freeShippingApplied}` or the same 422s. Same company-membership and address checks as placement; no stock hold, no write. For E3.4.
- **Zones are read on every pricing call** (one query, no cache). Cache short-term if it shows up in profiles.

**PO number.** Optional `purchaseOrderNumber` on `POST /api/v1/orders`; company orders only (a personal order with one is a 400). Trimmed, blank = none, 1-40 ASCII letters/digits/space and `- _ . # /`; anything else (control characters, `=`, `<`, Bangla) is a 400 before stock is held. Stored on `orders`, returned in `OrderDto.purchaseOrderNumber`, indexed `(company_id, purchase_order_number)` for the later search. Part of the idempotency hash (appended only when present, so keys stored before E8.2 still replay): the same `Idempotency-Key` with another PO number, or none, is 409 `IDEMPOTENCY_KEY_REUSED`.
