## HANDOFF (E8.1)
**Moved (backend only, no endpoints, no tariff data anywhere):** `backend/src/Mechware.Domain/Shipping/` (`ShippingRateCard`, `ShippingZone`, `ShippingCalculator`), `backend/src/Mechware.Application/Shipping/IShippingRateProvider.cs`, `backend/src/Mechware.Infrastructure/Shipping/ShippingRateProvider.cs` (AsNoTracking, split query, active zones only), `backend/src/Mechware.Infrastructure/Persistence/Configurations/ShippingConfigurations.cs`, migration `AddShippingZones` (tables `shipping_zones`, `shipping_zone_districts`, `shipping_rate_bands`; empty). Tests: `~Mechware.UnitTests.Shipping` and `~Mechware.IntegrationTests.Shipping`.

**Model.** Zone = code, EN/BN name, active flag, a set of **district** ids (`bd_locations` rows with level `district`; FK, restrict) and one rate card. Rate card = weight bands `(maxGrams, feeMinor)` + optional free-shipping threshold (subtotal >= X) + optional heavy-unit grams + optional oversize side mm + fee cap. A district can be in only one zone: the primary key of `shipping_zone_districts` is `district_id` (DB refuses), the domain refuses a duplicate in one zone, the calculator refuses a district found in two zones passed to it. The existing `BdLocation.ShippingZone` text column (`inside_dhaka` ...) is NOT used by this model; E8.4 may drop or ignore it.
**Calculator** `ShippingCalculator.Calculate(zones, districtId, lines, orderSubtotalMinor)` returns `Priced(ZoneId, PerSeller[], TotalMinor, FreeShippingApplied)`, `QuoteOnly(Reasons[])` or `NoZone`; throws `ValidationException` for no weight (`NO_WEIGHT`), quantity <= 0, empty order, negative subtotal.
- Units: weight whole grams (`ShippingLine.GramsFromKg` = ceiling of `ProductVariant.WeightKg * 1000`), sides whole mm (`MmFromCm` = ceiling of cm * 10; sides live on `Product`, not the variant). Money poisha, no floats.
- One parcel group per seller: seller weight = sum(qty * unit grams); fee = first band with `weight <= maxGrams` (exactly maxKg stays, +1 g moves up). Heavier than the last band = `QuoteOnly` (`ABOVE_LAST_BAND`), never a guessed fee.
- Free shipping: order subtotal >= threshold makes every seller fee 0 (priced, `FreeShippingApplied`). Quote-only wins over free.
- Quote-only rules: any single unit > `HeavyUnitGrams` (`HEAVY_ITEM`), any side > `OversizeDimensionMm` (`OVERSIZE_ITEM`; unknown sides are not oversize), or above last band. Reasons carry variant/seller ids. The brief has no product-level heavy flag, so this is a configurable rule, as asked.
- Total = exact sum of per-seller fees (computed once); fee <= cap; band fees must be non-decreasing and <= cap (card validation), so heavier is never cheaper.
- `QuoteOnly` is the whole order, not per seller (one decision for staff).

**Moved (backend only):** seam `backend/src/Mechware.Application/Shipping/IOrderShippingQuoter.cs` (codes `SHIPPING_NOT_AVAILABLE`, `SHIPPING_QUOTE_ONLY`, `VARIANT_WEIGHT_MISSING`), implementation + `ShippingOptions` in `backend/src/Mechware.Infrastructure/Shipping/OrderShippingQuoter.cs`, pricing step in `backend/src/Mechware.Infrastructure/Orders/OrderService.cs` (`PriceAsync`, `DistrictIdAsync`, `QuoteShippingAsync`), new 422 exception `backend/src/Mechware.Domain/Common/Exceptions/UnprocessableException.cs` (mapped in `GlobalExceptionHandlingMiddleware`), PO number on `Order` (`NormalisePurchaseOrderNumber`), migration `AddOrderPurchaseOrderNumber` (`orders.purchase_order_number varchar(40)` + `ix_orders_company_po`), endpoint `POST /api/v1/orders/shipping-quote`. **How shipping is priced now.** `PriceAsync` loads the variants (weight from `ProductVariant.WeightKg`, sides from `Product`), applies promotions, prices the goods once with zero shipping to get the **free-shipping basis** = the sum of the line totals (after discounts, VAT included, shipping excluded; the same number in VAT-inclusive and VAT-exclusive orders, what the buyer sees), asks the quoter, then prices again with each seller's fee in `SellerTerms`. `OrderPricing` adds each fee once to its sub-order total; grand total = sum of sub-order totals. The client sends no money and nothing it sends is read (tamper test over HTTP).
- **Destination:** addresses and company sites keep the district as text (EN or BN name, checked against the location list when saved). `DistrictIdAsync` looks it up in `bd_locations` (level `district`; by name, then by division if two share a name). No match or ambiguous: null, which shipping refuses. The id is also written into the order's ship-to snapshot as `districtId` (E8.3 needs it for "same city"). No address migration was needed.
- **Refusals (HTTP 422, nothing reserved, no order):** no zone serves the district or district unknown: `SHIPPING_NOT_AVAILABLE`. Heavy, oversize or above the last band: `SHIPPING_QUOTE_ONLY` with `details[] = {field: reason code, message: SKU}` (buyer must use RFQ, D4). Variant weight <= 0: `VARIANT_WEIGHT_MISSING` naming the SKUs (checked before the calculator, never a 500, never free).
- **No zones yet (decision):** `Shipping:AllowFreeWhenNoZones`. Unset = on in Development/Testing, off elsewhere. On = shipping 0 **only while no active zone exists at all**; once one zone exists every destination is priced or refused. Outside Development/Testing the API refuses to start with it on (production fails closed). The Worker never places orders and gets the default (off).
- **VAT on shipping: NOT decided.** The fee stays a final amount with no VAT split (unchanged `OrderPricing` treatment; `TODO(E8, owner + tax adviser)` in `PriceAsync`). If shipping must carry VAT, it belongs in `OrderPricing` (one place), not in the quoter.
- **Preview:** `IOrderService.QuoteShippingAsync` / `POST /api/v1/orders/shipping-quote` (auth like placement; body = lines, shippingAddressId, companyId, couponCodes, shipToSiteId) returns `{perSeller:[{sellerId, shippingMinor}], totalMinor, freeShippingApplied}` or the same 422s. Same company-membership and address checks as placement; no stock hold, no write. For E3.4.
- **Zones are read on every pricing call** (one query, no cache). Cache short-term if it shows up in profiles.

**PO number.** Optional `purchaseOrderNumber` on `POST /api/v1/orders`; company orders only (a personal order with one is a 400). Trimmed, blank = none, 1-40 ASCII letters/digits/space and `- _ . # /`; anything else (control characters, `=`, `<`, Bangla) is a 400 before stock is held. Stored on `orders`, returned in `OrderDto.purchaseOrderNumber`, indexed `(company_id, purchase_order_number)` for the later search. Part of the idempotency hash (appended only when present, so keys stored before E8.2 still replay): the same `Idempotency-Key` with another PO number, or none, is 409 `IDEMPOTENCY_KEY_REUSED`.

**Open for the owner:** the free-shipping basis above (goods payable incl. VAT after discounts) is my call, confirm it; VAT on shipping; tariffs/zones (E8.1 list). `OrderService` now requires an `IOrderShippingQuoter` (test call sites pass `ShippingTestKit.DevelopmentQuoter`).

## HANDOFF (E8.3)
2026-11-16 · E8.3 ✅ + E8.3b ✅ (not committed) · Sonnet. Backend only, one migration `AddOrderDeliveryDeadlines` (`orders.confirmed_at`, `legal_delivery_deadline_at`, `courier_handover_deadline_at`, `deadline_same_city`, partial index `ix_orders_legal_deadline`; applied and checked on a scratch DB).

**FOR THE LAWYER (confirm or correct; the numbers are configuration, not code).** Rule implemented: the clock starts at the instant the order becomes **confirmed** (payment captured, or accepted on credit terms, directly or after approval). Legal delivery deadline = confirmation + **5 days** when the destination district is the district of a dispatch warehouse of a seller in the order, else + **10 days**; courier handover deadline = confirmation + **48 hours** (also for credit orders, which have no advance payment: please confirm). Calendar days and hours, not working days; no extension for weekends or holidays; an order is overdue strictly after the deadline instant (at the instant it is still on time). Config: `Delivery:SameCityDays` (5), `Delivery:OtherCityDays` (10), `Delivery:HandoverHours` (48); a value that is not a whole number above 0 stops the API at startup. Changing it affects only orders confirmed afterwards.

**Design.** `Mechware.Domain/Orders/DeliveryDeadlines.cs` (pure `Compute`), `Order.Confirm(deadlines, ...)` is the only way to reach Confirmed (`Order.Transition(Confirmed)` throws), so no path can confirm without deadlines. Three confirmation paths use it: payment webhook (`PaymentService`, via the port `IDeliveryDeadlineCalculator`), credit at placement and credit after approval (`OrderService`). Computed once, stored, never recomputed on read; no request body can carry them (tests send them and they are ignored). Order level, not per sub-order (sub-orders do not ship on separate dates yet). Orders confirmed before this unit have null deadlines and are never listed overdue (no invented dates).
- **"Same city" (simple, documented):** the order's ship-to `districtId` (E8.2) equals the `bd_locations` district named by the text `District` of a dispatch warehouse. A seller's dispatch warehouses are its own active warehouses, else the MECHWARE hub's (sellers have no district of their own). Strictest wins across sellers: one same-city or unknown seller makes the whole order same-city. Unknown (no ship-to district id, no warehouse, warehouse district not in the location list) = **5 days (fail strict)**, stored as `deadline_same_city = null`. Known weakness: the warehouse district is free text matched by name (EN or BN), like addresses; a typo in a warehouse district means "unknown", i.e. the short deadline.
- **Overdue query:** `IOrderDeadlineService.ListOverdueAsync(asOfUtc, page, pageSize)`; `GET /api/v1/admin/orders/overdue?page=&pageSize=` (permission `orders.view_all`, page size <= 50, most overdue first). Delivery overdue: past the legal deadline and status in Confirmed, Processing, Packed, Shipped, OutForDelivery, DeliveryFailed. Handover overdue: past the handover deadline and status in Confirmed, Processing, Packed. Delivered, Completed, Cancelled, Returned, Return*, Refunded are never listed. Items: orderId, orderNumber, status, districtId, district, both deadlines, two flags, hoursOverdue (the larger lateness); no name, phone, street or e-mail. The handover query has no index of its own (acceptable until volume shows otherwise).
- **Buyer:** `OrderDto.estimatedDeliveryBy` (additive, null until confirmed) = the stored legal deadline. `legalDeliveryDeadlineUtc` itself is not in the buyer DTO.
- Files: `Domain/Orders/DeliveryDeadlines.cs`, `Order.cs`, `Application/Orders/OrderDeadlineContracts.cs`, `Infrastructure/Orders/OrderDeadlineService.cs` (`DeliveryOptions`, `DeliveryDeadlineCalculator`, `OrderDeadlineService`), `OrderService.cs`, `Payments/PaymentService.cs` (new required ctor argument `IDeliveryDeadlineCalculator`; tests use `ShippingTestKit.Deadlines(db)`), `OrderConfigurations.cs`, `Api/Controllers/AdminOrdersController.cs`, `Program.cs` (startup guard). Tests: `UnitTests/Orders/DeliveryDeadlinesTests`, `IntegrationTests/Orders/OrderDeliveryDeadlineTests` (time travel through the real payment path), `OverdueOrdersEndpointTests` (401/403/200, paging, no personal data, client-sent deadlines ignored, buyer sees `estimatedDeliveryBy`).
- Not built: a console screen for the overdue list; notifications to staff or buyers about a missed deadline; a flag/penalty workflow; per-sub-order deadlines.

**Permissions (new, deliberate RBAC):** `shipping.view` = Support + Finance + Admin; `shipping.manage` = Admin only.

**Endpoints** (all under `/api/v1/admin/shipping`, envelope `{data}`; errors `{error:{code,message,details[{field,message}]}}`):
- `GET zones` (view) -> `[{id, code, nameEn, nameBn, isActive, districtCount, bandCount, version}]`, active and inactive, ordered by code.
- `GET zones/{id}` (view) -> `{id, code, nameEn, nameBn, isActive, version, districts:[{id,nameEn,nameBn}], rates:{bands:[{maxGrams,feeMinor}], freeShippingThresholdMinor, heavyUnitGrams, oversizeDimensionMm, maxFeeMinor}, createdAtUtc, updatedAtUtc}`. 404 unknown.
- `POST zones` (manage) body `{code, nameEn, nameBn, isActive, districtIds[], rates{...as above}}` -> 201 + detail + `Location`. Code is lower-cased, `^[a-z0-9][a-z0-9_-]{0,39}$`. Client-sent `id`, `version`, timestamps, authors are ignored.
- `PUT zones/{id}` (manage) whole-document replace: same body plus **required `expectedVersion`** (the `version` the editor loaded). Stale = 409 `SHIPPING_ZONE_STALE`; missing = 400 field `expectedVersion`; a different `code` = 400 (the code never changes; omit it or repeat it). Response = new detail (new `version`). Version is the row's `xmin` (read in SQL, no model change); the row is locked `FOR UPDATE` for the edit.
- `DELETE zones/{id}` (manage) -> 204; 409 `SHIPPING_ZONE_ACTIVE` while active (deactivate first via PUT); 404 unknown. Districts and bands cascade.
- `POST zones/preview` (view; note: the path is `zones/preview`) body `{districtId, subtotalMinor, lines:[{sellerId?, quantity, unitWeightGrams, lengthMm?, widthMm?, heightMm?}]}` -> `{outcome: "Priced"|"QuoteOnly"|"NoZone", zoneId, zoneCode, perSeller:[{sellerId, shippingMinor, chargeableGrams}], totalMinor, freeShippingApplied, reasons:[{code: HEAVY_ITEM|OVERSIZE_ITEM|ABOVE_LAST_BAND, lineIndex?, sellerId?}]}`. Runs `ShippingCalculator` on the ACTIVE zones exactly like order pricing (inactive zone = NoZone); writes nothing (no audit row either). Lines without `sellerId` count as one seller. Limits: 1-200 lines, qty <= 100,000, weight 1-1,000,000 g.
- `GET coverage` (view) -> `{activeZoneCount, covered:[district], uncovered:[district]}`, district = `{districtId, nameEn, nameBn, divisionNameEn, zoneId, zoneCode, zoneActive}`. `uncovered` = no ACTIVE zone (production refuses orders there); a district held by an inactive zone is listed there with its `zoneCode` and `zoneActive:false`.

**Rules and errors.** Sanity limits (400, field names like `rates.bands[0].maxGrams`): band weight 1..1,000,000 g (1,000 kg), at most 20 bands, fee and cap <= 10,000,000 poisha (100,000 BDT), free threshold <= 10^10 poisha, heavy unit <= 1,000,000 g, oversize side <= 20,000 mm, <= 100 districts, names 1-100 chars. Then the domain card rules (400 field `bands`): same weight twice, heavier band cheaper, fee above the cap. District ids must exist at level `district` (400 `districtIds`). A district already in ANOTHER zone, active or not (the DB key is the district id), = 409 `SHIPPING_DISTRICT_ALREADY_IN_ZONE`, message names the district and the owning zone code and state; duplicate zone code = 409 `SHIPPING_ZONE_CODE_TAKEN`; a race on either = 409 `SHIPPING_ZONE_CONFLICT`. Console hint: send fees in poisha (x100 of BDT) and show the district/zone owner from the 409 text.

**Audit.** Explicit rows `shipping.zone.created` / `.updated` / `.deleted` (entity `shipping_zones`, actor + ip, old and new JSON summary of code, active, district ids, bands, cap, thresholds) in addition to the interceptor's own entity rows.

**Proof it feeds orders.** `AZoneCreatedThroughTheApi_IsWhatAProductionHostPricesOrdersFrom` runs a Production-mode host: quote refused `SHIPPING_NOT_AVAILABLE` before, after an Admin POST the quote and placed order carry the entered fee once.
