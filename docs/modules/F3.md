Handles `OrderPlacedEvent` -> `order-confirmed` to the buyer (skipped while the order is `pending_approval`) and the new `ApprovalRequestedEvent` (raised in `ApprovalRequest.Create`) -> `approval-needed` to the approver of the current step (skipped if no longer pending or subject is not an order). Recipient, name, locale (`User.Locale`, only `bn` else `en`), order number, total (`NotificationFormat.Money` -> "BDT 12,500.00") are read from the DB at send time; the payload holds no PII.
- Idempotency: the outbox only guarantees at-least-once, so `NotificationDispatcher` claims a row in new table `notification_log` (unique `event_id, recipient_user_id, template_key`; migration `NotificationLog`) with `INSERT ... ON CONFLICT DO NOTHING` before sending; 0 rows = already handled, skip. Success -> `sent`. Transient failure (network, SMTP 4xx) -> claim deleted, error rethrown after the other recipients were served, so the relay's normal retry (max 10) resends only that one. Permanent (template error, malformed address, SMTP 5xx mailbox refusals) -> `failed`, logged masked, never retried. Remaining gap: crash after SMTP accepted but before commit can duplicate once (inherent without 2PC). Note the relay runs all publishers per message, so a transient failure here also re-runs the other publishers (search queue push is idempotent for the indexer).
- Links: `Storefront:BaseUrl` (env `Storefront__BaseUrl`), validated in `AddNotifications`: required and https outside Development/Testing (hosts refuse to start without it, like `Email__Host`); default `http://localhost:3000` in dev, localhost http allowed only in dev.
