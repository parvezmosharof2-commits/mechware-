## HANDOFF
2026-11-13 · F3a.1 done. Evidence: `dotnet test` UnitTests `~Notifications|ModuleBoundary|Layering` 26 passed / 0 skipped; IntegrationTests `~Notifications` 1 passed / 0 skipped (real Mailpit); Security + SearchApi integration tests still green (90 passed).
- Port (`Application/Notifications/NotificationContracts.cs`): `INotificationSender.SendEmailAsync(EmailMessage)`, `INotificationTemplates.Render(key, locale, Dictionary<string,string>) -> RenderedEmail(Subject, Html, Text)`, `NotificationMessage(To, Locale, TemplateKey, Model)` (for F3a.3 to carry through the outbox), `NotificationTemplateException`.
- Engine: `Infrastructure/Notifications/EmbeddedTemplates.cs`. Files in `Notifications/Templates/` are embedded (`WithCulture="false"` is needed, otherwise MSBuild treats `.en.`/`.bn.` as a culture and drops the html files): `{key}.{en|bn}.subject.txt|html|txt` plus `_layout.{locale}.html|txt` (brand header, "You get this email because…" footer, inline CSS, no external assets). Placeholder `{{name}}`; html values HTML-encoded, subject/text plain (CR/LF in the subject collapsed). Missing value, unknown key, bad key, bad locale -> `NotificationTemplateException`. Missing bn file only -> en + warning.
- Seeded keys and their model: `order-confirmed` (customerName, orderNumber, total, orderUrl), `approval-needed` (approverName, requesterName, orderNumber, total, approvalUrl), `quote-sent` (customerName, quoteNumber, total, validUntil, quoteUrl). The url values land in `href`: callers must pass only our own https URLs. No secrets or card data in any template.
- Adapter: `SmtpEmailSender` on `System.Net.Mail.SmtpClient` (no MailKit in the repo, no new package), multipart text+html, base64 UTF-8, recipient masked in logs. `LoggingEmailSender` when `Email:Host` is empty in Development/Testing. Options `Email:{Host,Port,UseTls,Username,Password,FromAddress,FromName,TimeoutSeconds}`; `AddNotifications(options, requireRealSetup)` is wired in Api and Worker. **Outside Development/Testing both hosts now refuse to start without `Email__Host` and `Email__FromAddress`** (Production-env integration tests got dummy values).
- Dev: compose `mailpit` pinned to `axllent/mailpit:v1.21` (SMTP 1025, UI/API 8025; the service already existed as `:latest`); Development appsettings for Api + Worker point at it. Test helper `MailpitFactAttribute` (probe `/api/v1/info`; env `MECHWARE_TEST_MAILPIT_API`, `MECHWARE_TEST_MAILPIT_SMTP_PORT`).
- Not done / for F3a.3: no outbox consumer, no retries or idempotency, no SMS. Tip when running tests while a dev API holds `Mechware.Api/bin`: add `-p:BaseOutputPath=<other dir>/`.
