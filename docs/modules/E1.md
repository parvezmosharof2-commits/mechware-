## HANDOFF (E1.2)
**Store (`RedisCartStore`):** one hash per cart at `CartOwner.StoreKey`: `e` = ETag (128 random bits, 32 lowercase hex; random, so a cart that changes and changes back still conflicts), `v` = JSON `{schema:1, version, items[{variantId, quantity, seenUnitNetMinor}]}`. Three single-key Lua scripts (read + touch, CAS save, discard-if-unchanged): atomic, cluster-safe, no hash tag needed. `null` expected ETag = SET NX; a malformed ETag is a Conflict without a Redis call; a Conflict writes nothing (not even the TTL).
- **TTL (decided):** guest 7 d, user 30 d, sliding on every save **and** every read that finds the cart (EXPIRE inside the read script). Reason: a B2B buyer reopens a cart for days while waiting for approval without changing it; save-only sliding would expire it while in use. Matches the token being re-issued on each response.
- **Stored data is not trusted:** size checked in Lua before fetching (≤ 32 KB), strict JSON (unknown, duplicate or missing fields refused), `OrderLimits` re-checked by `RedisCartStore.Violation` (the same check on save → `ValidationException`). Unreadable → log (kind, id prefix, reason, size; never content), delete if unchanged, read as absent (otherwise `Save(null)` would conflict forever). Schema newer than this build → kept + 503 (rolling deploys); schema changes take two releases (reader first), see `SchemaVersion`.
- Redis error or timeout → `ServiceUnavailableException("CART_UNAVAILABLE")` (503), never an empty cart.

**Token (`GuestCartTokenService`):** `b64url(id 16 | expiry 8 | version 1) "." b64url(HMAC-SHA256)`, 78 chars, cookie-safe. Key = HKDF(`GuestCart:TokenKey`, "mechware/guest-cart-token/v1"); `GuestCart:PreviousTokenKeys` (comma-separated) only verify (rotation: keep the old key 7 days). `Validate`: exact length → canonical base64url → MAC with `FixedTimeEquals` over all keys (no early exit) → version → expiry (also refuses > 7 d + 5 min ahead) → non-empty id; null on anything, never throws. The id is a random v4 GUID (122 bits, not guessable); the token gives integrity, not secrecy.
**Config:** `AddCartStore(configuration, requireRealSetup)` in `backend/src/Mechware.Infrastructure/DependencyInjection.cs` (one line in `backend/src/Mechware.Api/Program.cs`) refuses startup outside Development/Testing without a key, with < 32 bytes, all-equal bytes, or the published dev key (also as a previous key). Staging: `GUEST_CART_TOKEN_KEY` required (`${VAR:?}`), given to the `api` container only; H3 card lists it. `DbBackedFactory` sets a test key for Production-like test hosts.
**Tests:** `~Mechware.UnitTests.Cart` (token: forged, every bit/char flipped, expired at the second, too-long expiry, versions, truncated, huge, non-base64, 20k random strings, rotation, other key, Cecil check for `FixedTimeEquals`; key options; limits) and `~Mechware.IntegrationTests.Cart` (round trip, stale ETag, 50 concurrent writers / 50 concurrent creators over two connections → exactly 1 wins, TTLs + sliding, 25 unreadable payloads + 7 broken key shapes → absent and discarded, newer schema → 503 and kept, user/guest keys apart, delete idempotent, Redis down → 503, Production startup refused without a real key). Mutants killed: no signature check, CAS ignoring the ETag, no expiry check, no limit re-check on load, + 7 more; 2 redundant layers survive alone (canonical re-encode, exact length) but are killed together. Threat model: `docs/security/THREAT_MODEL_PRICING_QUOTES_PAYMENTS_INVOICING.md` §৯ (CT1–CT11).

**E1.3 must:** read the token only from a `__Host-` cookie (HttpOnly, Secure, SameSite=Lax, Path=/), never from URL, body or header; re-issue it on every cart response (sliding); build `CartOwner.FromValidatedGuestToken` only from `Validate`'s result; mint `GuestCartId.New()` only on the first write, not on GET; limit new guest carts per IP (CT11); on Conflict re-read, re-apply, retry (bounded) then 409; keep prices server-side (tamper test).
**E1.4 must:** merge with `CartEngine.Merge`, CAS-save the user cart (retry on Conflict), **only then** `DeleteAsync(guest)` and expire the guest cookie, so a replayed guest token afterwards sees an empty cart (CT10); new guest id after logout. `DeleteAsync` is unconditional: a guest add racing the login can be lost; add an ETag-guarded delete if that matters.
**Owner / H3b:** Redis holding carts must not evict (`noeviction` or a dedicated instance) + `maxmemory` alert; Redis AUTH/TLS in production; `GuestCart__TokenKey` in the secret store.
