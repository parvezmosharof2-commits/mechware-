Clock behind (earlier instant or earlier fiscal year than `last_issued_at`) → error log `ALERT INVOICE_CLOCK_BEHIND` + `InvoiceClockBehindException` (not a DomainException, so the API answers 500 as ADR §4 says; the Architecture rule forbids non-DomainException types in Domain, hence it lives in Application). Equal instants are allowed.
- **Table `invoice_number_counters`** (migration `AddInvoiceNumbering`): PK `(seller_id, series)`, `fiscal_year` int (0 before the first issue), `next_serial` bigint, `last_issued_at` timestamptz null; FK seller RESTRICT (outgoing only; no incoming FK, so `FOR UPDATE` is safe); CHECKs: series list; state `(0, 1, null)` or `(2000-9998, ≥ 2, not null)`. Guard trigger (SQLSTATE 23000, message starts with the table name): INSERT only as `(0, 1, null)`; UPDATE only `+1` in the same year or rollover to a later year with `next = 2`; seller/series never change; `last_issued_at` never goes back; `fiscal_year` must equal the July-June year of the Dhaka date of `last_issued_at` (so a UTC-year bug fails in the DB too); no DELETE, no TRUNCATE. Migration Up → Down (to `AddReturnRequests`) → Up proven by `Migration_AddInvoiceNumbering_GoesUpDownAndUpAgain` (scratch DB `mw_e62_*`); not applied to `mechware`.
